## 本轮修复

1. **高优先级：重试耗尽未触发停止。** `fillStageTaskWithReopenRetry` 最终抛出 `STAGE_DRAMA_FILL_FAILED`，runner 却只对 `STAGE_TASK_BLOCKING_FAILURE` 停止。统一最终错误码，确保内容或商品选择连续重开失败后停止。增加实际重试函数的模拟测试，与已有 runner 阻塞停止、drain 持锁测试配合验证。
2. **中优先级：保存超时重复等待。** `waitStageSubmitResult` 先创建一次弹窗隐藏等待，之后又启动一次完整等待，单次失败可能消耗两个 15 秒窗口。复用首次等待，保留弹窗隐藏判定及错误提示；测试确认成功、超时路径均只等待一次且清理响应监听器。这减少失败路径的额外等待，不代表正常批次提速。
3. **中优先级：性能报告遗漏失败并跨运行累计。** `endWithError` 提前将状态置为 ERROR，使 `endSpan` 跳过计时。改由 `endSpan` 统一结束，重复结束保持原错误。runner 取得锁后重置统计，按次保存独立报告，提前失败同样保存。日志目录创建失败也被报告写入保护捕获。
4. **中优先级：Windows 不可用端口使桌面启动失败。** 首次全量测试实际遇到 `listen EACCES`，原代码仅对 `EADDRINUSE` 尝试下一端口。纳入 EACCES，保留有限尝试次数，并阻止端口超出 65535。
