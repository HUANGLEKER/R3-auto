# 第一批工程升级验证（2026-09-26）

本次完成运行锁、任务结果状态、接口校验和桌面 IPC 四项升级。不包含 SQLite 迁移或断点恢复。

## 行为变化

- 运行锁：原子创建 `full_flow_unified.run.lock.acquire` 目录，串行处理锁创建和失效锁回收；释放必须匹配 PID 和随机令牌。空锁、损坏锁、无法证明进程已退出的情况均阻断。进程在获取锁的短临界区内崩溃可能遗留获取目录，程序不按超时强抢，需先核对所有运行实例再处理。
- 任务结果：单项填写完成为 `filled`，整页请求期间为 `submitting`，确认业务成功后才转为 `success`。超时、断线或无法确定的响应为 `uncertain`，不进入失败重试。已确认冲突转为失败，其余槽位保留并等待递补提交。控制台、SSE、汇总计数、结构化日志和 CSV 使用同一成功判定。
- 参数校验：增加固定版本 Zod 依赖；启动、配置保存及从本地文件读取的有效运行配置均校验。长 ID 输入只接收字符串，复制 URL 限定平台 HTTPS 复制页，ROI 为正十进制数，面板限定四种类别。非法 JSON、未知字段和旧续搭参数返回 400，校验失败不写配置。OpenAPI 在无损解码后校验响应包、列表字段和分页类型，继续保留现有业务资格检查。
- 桌面通信：后端通过专用 IPC 回传实例标识、PID 和真实监听端口，桌面不再扫描端口或解析 stdout 的 URL。退出通过 IPC 请求停止，等待 runner drain、断开自身 CDP 连接后关闭 HTTP/SSE 服务。子进程异常退出会清除旧服务地址。

## 验证结果

- 统一测试：145 项通过，0 失败，0 跳过。
- TypeScript 类型检查通过；前端和桌面 JavaScript 语法检查通过。
- 6 个独立子进程同时首次获取锁，以及同时回收失效锁，两种情况均只有一个实例成功。
- 真实 runner 使用模拟外部操作，覆盖提交成功、未知结果、重复冲突递补、停止、提交未开始和填单阻塞；验证 drain 完成前锁仍存在。
- HTTP 验证非法参数不写配置、CSV 状态与成功数一致；真实浏览器验证 SSE 更新、状态筛选和展示，无页面脚本错误。
- IPC 验证端口被其他服务占用、错误实例标识、stdout 伪就绪信息、提前退出和握手超时。
- 全部业务接口使用模拟，没有提交真实平台任务。旧断点文件不读取、不写入、不清除。
