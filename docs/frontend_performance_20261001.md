# 大批量前端与搭剧模块完善（2026-10-01）

## 结果表格

`ExecutionTable` 使用独立 `useVirtualRows` Hook，以 44px 固定行高计算视口范围，向上下各预留 8 行。当前最大 460px 的滚动区域最多渲染 27 条数据行；其余高度用表格占位行保留。未增加外部依赖。

固定列宽、名称截断及单行单元格保证滚动时行高和列宽稳定；横向滚动和粘性表头保留。筛选及搜索改变时回到顶部，筛选后的逻辑行号和总行数通过 ARIA 属性保留。只裁剪 DOM 渲染范围，完整数据仍用于筛选、详情、复制和后端 CSV 导出。`React.memo` 避免日志变化引起结果表格重复渲染。

## 高频日志

日志缓冲模块 `log_batcher.ts` 每 100ms 批量消费；同批次只追加一次日志状态，流水线步骤也只更新到本批最新的有效步骤。缓冲和显示各保留最近 800 条；完整日志仍由后端写入文件。

完整 SSE 快照替换显示日志前取消旧缓冲，避免重复追加；重连、新运行、服务端或本地清空以及组件卸载取消待发送批次。任务事件到来前先刷出前置日志，保持日志步骤与任务事件的先后关系。结束状态不完整包含日志时先刷出尾部日志，再更新状态；完整快照则以快照为准。

## 模块拆分

`stage.ts` 从约 2078 行降至 191 行，保留填单与保存核验编排，以及兼容旧调用方的导出。

| 模块 | 职责 |
| --- | --- |
| `stage_dom.ts` | 子任务容器、统计、重新加载 |
| `stage_drama_select.ts` | 内容搜索、真实输入、候选与选中证据 |
| `stage_product_select.ts` | 商品匹配方式、搜索与选择 |
| `stage_selection_policy.ts` | 不依赖浏览器的选择证据判断 |
| `stage_form_fields.ts` | IAA/IAP 与 ROI 定位、填写及核验 |
| `stage_dialog.ts` | 打开、放弃修改、清理与退出确认 |
| `stage_retry.ts` | 通过注入操作执行的整轮重试策略 |
| `stage_automatch.ts` | 兼容自动匹配的观察逻辑 |

模块之间没有回引 `stage.ts`，避免循环依赖。内容/商品延期规则、取消修改失败阻断、未知填单失败阻断、保存实际值核验、整页提交规则保持不变。选择策略额外拒绝空 ID 作为选中证据。
